\affil*[1]{\orgdiv{Process and Data Science Group}, \orgname{RWTH Aachen University},

\affil[2]{\orgname{Celonis}, \orgaddress{\city{Munich}, \country{Germany}}}

\abstract{Event logs, process trees, and Petri nets describe process behavior from different perspectives, yet most learning methods are tied to one representation. This makes it difficult to search across artifact types, compare heterogeneous process models, or reuse learned knowledge when only a different representation is available. We present \model, a behavior-supervised multimodal system that maps all three artifact types into a shared vector space and decodes any supported input into a process tree. Training examples are organized as behavior families: a designated process-tree target, alternative Petri-net realizations, and finite event-log observations, together with explicit records of the visible-trace and partial-order relations shared by each pair. On unseen synthetic families generated under the same design, the learned space supports within- and cross-modal retrieval and reflects the experiment-specific behavioral distance used in the study. The generation results are substantially weaker. Grammar constraints ensure that every output is a well-formed process tree that can be converted to a Petri net, but they do not ensure that the output preserves the source behavior; event-log decoding also remains below specialized process discovery in conformance. Two real-log cases show the same underfitting pattern. \model should therefore be viewed as a shared representation and retrieval layer that can propose process-tree candidates for subsequent validation, rather than as an autonomous replacement for process discovery.}

\keywords{process mining, multimodal representation learning, behavior supervision, process trees, Petri nets, event logs, grammar-constrained decoding}

\section{Introduction}\label{sec:introduction}

Process-mining work rarely begins and ends with a single representation. Operational systems produce event logs, process-discovery methods return process trees or Petri nets, and analysts may maintain reference models in yet another notation. These artifacts may describe closely related behavior, but their structures are fundamentally different. Consequently, tasks such as finding the process model that best matches a log, comparing models written in different notations, or reusing knowledge learned from one artifact type usually require separate representations and task-specific pipelines.

Figure~\ref{fig:intuitive-example} illustrates the opportunity. The same small process can be observed as a finite event log, organized as a process tree, or represented explicitly as a marked Petri net. A shared representation could place corresponding artifacts near one another and thereby support cross-modal retrieval and comparison. It could also provide a common interface for translation into a selected exchange format. This translation is not ordinary file conversion, however. A finite log contains only observed executions, and different process-model structures can generate the same visible traces. Even two models with the same complete trace language may differ in their concurrency or causal structure.

\input{figures/intuitive-example}

We introduce \model, which treats event logs, process trees, and Petri nets as three modalities of process behavior. A modality-specific encoder maps each artifact to a shared semantic vector for retrieval and comparison, while a shared grammar-constrained decoder translates any supported source into a process tree. The central training unit is a behavior family: a designated tree target, multiple Petri-net realizations, and multiple finite log observations, accompanied by explicit relation metadata. This metadata distinguishes differences that should be ignored, such as identifier renaming or finite-sample variation, from differences that should remain visible, such as true concurrency versus an explicit enumeration of interleavings.

The evaluation separates two capabilities that are easy to conflate: learning a useful common representation and generating a behaviorally faithful process model. We test on families that are absent from training but are generated under the same synthetic design. Within this scope, the paper asks:

\begin{description}
\item[\RQone:] Does the shared space place related artifacts near one another, and do its distances reflect the experiment-specific behavioral ordering?
\item[\RQtwo:] When a valid process tree is decoded, how much of the source behavior is preserved?
\item[\RQthree:] How useful is the representation for cross-modal retrieval, and how does event-log-to-tree decoding compare with specialized process discovery?
\end{description}

The main result is asymmetric. Behavior-supervised training produces useful cross-artifact neighborhoods and retrieval, but syntactically constrained generation remains behaviorally unreliable. The contribution is therefore not only a multimodal architecture, but also a relation-aware supervision scheme and an evaluation that clearly separates syntactic validity, representation quality, and behavioral fidelity. The released generator, checkpoint records, and evaluation artifacts expose both the successful and unsuccessful parts of the neural system.

\section{Background and related work}\label{sec:related}

We position \model along three lines of work: process representations and discovery, representation learning for process artifacts, and multimodal alignment with constrained generation.

\subsection{Process representations and discovery}

An event log records completed executions but only partially samples the behavior of an underlying process. A process tree composes activities and silent steps through sequence, exclusive choice, parallelism, and loop operators. Its block structure permits conversion into sound workflow nets. A Petri net expresses places, transitions, arcs, and markings directly and can represent non-block structures not expressible by the chosen tree grammar \citep{vanDerAalst2016,Kourani2026}.

Classical process discovery accepts an event log and returns a process model. Inductive Miner recursively detects cuts and returns a sound block-structured result \citep{Leemans2013}. We use the PM4Py implementation for conversion, simulation, and evaluation \citep{Berti2023PM4Py}. Learned discovery instead estimates a process model from examples; graph-neural discovery is one relevant direction \citep{Sommers2023}. \model additionally accepts existing process trees and Petri nets, represents all three artifact types in one space, and supports retrieval as well as generation. Inductive Miner is therefore a baseline specifically for the event-log-to-process-tree part of the system, not for the representation-learning task as a whole.

No single score captures every aspect of process-model quality. Fitness asks whether the process model can reproduce the executions observed in a log. Precision asks whether it permits substantially more behavior than the log supports \citep{Adriansyah2013}. Distributional summaries such as directly-follows relations are cheaper to compute, but omit longer-range dependencies and may not distinguish concurrency from interleaving \citep{vanDerAalst2019DFG}. We therefore report several complementary measures rather than treating one score as complete behavioral equivalence.

\subsection{Representation learning for process mining}

Trace-encoding methods range from handcrafted features to sequence models; their assumptions and performance vary considerably by task \citep{Barbon2023}. Earlier work learned representations at activity, trace, log, and model levels \citep{DeKoninck2018}. Petri-net embeddings have also been learned from graph structure \citep{Colonna2024}, and graph distances can be compared with model-similarity measures \citep{Dijkman2011}. These approaches establish the value of vector representations but generally do not align raw logs, hierarchical trees, and marked Petri graphs in one behavior-supervised space.

A concurrent direction uses in-context learning on event logs for predictive monitoring \citep{Berti2026ICFM}. That setting centers on one input modality and prediction over cases. \model instead aligns multiple artifact types and produces complete structured process models. Predictive monitoring and artifact-level translation address different units of analysis and are complementary rather than directly competing tasks.

\subsection{Multimodal alignment and constrained generation}

Contrastive multimodal learning demonstrates that paired observations can define a shared space without requiring identical encoders \citep{Radford2021}. Supervised contrastive objectives allow all members of a semantic class to act as positives \citep{Khosla2020}. Our training examples are organized into behavior families, but family membership is not used as an unconditional equivalence label. Exact visible-language identifiers and partial-order identifiers determine which artifact pairs are treated as strong positives and which pairs provide only a weaker ordering constraint. Variance and covariance regularization reduce representation collapse without imposing a probabilistic prior \citep{Bardes2022}. Here, collapse is the degenerate situation in which many unrelated artifacts receive nearly identical vectors.

Transformers provide the attention mechanism used in the process-tree encoder, set-attention component, and decoder \citep{Vaswani2017}. The event-log encoder must additionally be invariant to trace order, motivating set attention \citep{Lee2019}. For output, grammar-constrained decoding can guarantee syntactic structure even when model probabilities are imperfect \citep{Geng2023}. Our decoder extends this principle with explicit operator arities, source-activity masking, contextual copy scores, and deterministic completion when the search budget is exhausted.

\section{Problem formulation and research questions}\label{sec:setting}

Training examples are generated as families rather than as independent triples. Consider a process that first registers a request and then either accepts or rejects it. The repeated prefix can be represented structurally in more than one way:
\begin{equation}
T=\mathsf{XOR}\bigl(
  \mathsf{SEQ}(\textsf{register},\textsf{accept}),
  \mathsf{SEQ}(\textsf{register},\textsf{reject})
\bigr).
\label{eq:worked-family}
\end{equation}
One Petri-net realization, $N^{(1)}$, has a distinct transition labeled \textsf{register} on each choice branch. A second realization, $N^{(2)}$, uses one shared \textsf{register} transition followed by two silent routing transitions. Their internal structures differ, but both allow exactly
\[
\langle\textsf{register},\textsf{accept}\rangle
\quad\text{and}\quad
\langle\textsf{register},\textsf{reject}\rangle.
\]
The generator creates two finite logs from this common trace pool. The cycled-coverage observation repeats available variants evenly before shuffling, whereas the resampled observation draws variants independently with replacement. Pairing each log with each realization gives the four rows in Table~\ref{tab:worked-family}.

The four rows are deliberately not treated as four independent processes. They show two kinds of variation around one designated target: structural variation between the Petri-net realizations and observational variation between the finite logs. Keeping the four rows together lets the learning objective compare these variations directly and prevents related artifacts from leaking across data splits. Family membership organizes the comparisons, while the relation record determines whether a particular pair is equivalent under both recorded semantics or related under a weaker notion. We now formalize the artifact types and tasks illustrated by this example.

Let $\mathcal{A}$ be a finite activity alphabet and $\tauact$ an invisible activity. A trace is a word $\sigma\in\mathcal{A}^{*}$, and an event log $L$ is a finite multiset of traces. A process tree $T$ is generated by
\begin{equation}
T ::= a \mid \tauact \mid \mathsf{SEQ}_{k}(T_1,\ldots,T_k)
 \mid \mathsf{XOR}_{k}(T_1,\ldots,T_k)
 \mid \mathsf{AND}_{k}(T_1,\ldots,T_k)
 \mid \mathsf{LOOP}(T_1,T_2),
\label{eq:grammar}
\end{equation}
where $a\in\mathcal{A}$ and $k\geq2$. A labeled Petri net is a tuple $N=(P,U,F,\ell,m_0,m_f)$ with places $P$, transitions $U$, flow relation $F$, labels $\ell:U\rightarrow\mathcal{A}\cup\{\tauact\}$, and initial and final markings $m_0,m_f$.

The operators have their usual process-tree meaning. \textsf{SEQ} executes its children in order, \textsf{XOR} selects one child, and \textsf{AND} permits its children to proceed concurrently. In $\mathsf{LOOP}(T_1,T_2)$, the body $T_1$ executes at least once and the redo branch $T_2$ determines how another iteration is entered. The grammar produces block-structured trees and cannot express every valid Petri-net topology.

Each family contains one designated process-tree target, which serves as the unique supervised output for decoding. It is canonical within the dataset construction, but need not be the only process tree compatible with a finite log. Its compact grammar supports constrained generation and conversion into a sound workflow net, while limiting the output to block-structured behavior.

A \emph{behavior family} is a data-generation and split unit containing related artifacts. Family membership alone does not assert equivalence under every behavioral semantics. The accompanying relation record states whether two artifacts share their complete visible trace language, their recorded partial-order semantics, both, or only bounded evidence. These recorded relations, rather than family membership alone, determine how the pair is used during training.

Throughout the paper, we distinguish three levels. The \emph{underlying specification} is the designated tree before observation-specific relabeling. An \emph{artifact realization} is a process tree or Petri-net structure related to that specification under a declared relation. A \emph{finite observation} is an event log sampled from the trace pool.

Formally, family $f$ contains a designated tree $T_f$, two Petri-net realizations $N_f^{(1)},N_f^{(2)}$, and two event-log observations $L_f^{(u)},L_f^{(r)}$, where $u$ denotes the cycled-coverage implementation mode and $r$ the independent resample. Their pairing is
\[
\begin{array}{c|cc}
 & L_f^{(u)} & L_f^{(r)}\\
\hline
N_f^{(1)} & (T_f,N_f^{(1)},L_f^{(u)}) & (T_f,N_f^{(1)},L_f^{(r)})\\
N_f^{(2)} & (T_f,N_f^{(2)},L_f^{(u)}) & (T_f,N_f^{(2)},L_f^{(r)})
\end{array}
\]
Thus one family produces four aligned rows. For readability, the notation suppresses observation-specific activity relabeling. The family has one designated tree before relabeling, but the stored rows contain consistently relabeled copies $T_f^{(u)}$ and $T_f^{(r)}$, together with the corresponding relabeled nets and logs. The two stored tree targets are therefore surface-different copies of the same underlying target. Each log observation and Petri-net realization participates in two rows.

For modality $m\in\{T,L,N\}$, an encoder produces two representations. The contextual memory $H_m$ retains detailed, local information and is used by the decoder. The normalized vector $\vect z_m$ is a compact summary used for retrieval, distance calculations, and fusion. This distinction allows the same encoder to support structured generation and artifact-level comparison.

Cross-modal retrieval compares the compact vectors using cosine similarity. Direct translation conditions the process-tree decoder on the detailed source memory and returns a tree in Eq.~\eqref{eq:grammar}. Fusion is intentionally simple: it averages the available compact vectors,
\begin{equation}
\vect z_{\mathrm{fuse}}=\frac{1}{|S|}\sum_{m\in S}\vect z_m,
\qquad S\subseteq\{T,L,N\},
\label{eq:fusion}
\end{equation}
and projects their mean into decoder memory. Fusion is a baseline common interface rather than a learned reliability-aware aggregation mechanism. Translation is therefore always into a process tree, even when the source is a Petri net. These tasks instantiate \RQone--\RQthree{} from the Introduction.

\section{The ProcRosetta method}\label{sec:model}

\subsection{Behavior families as the supervision unit}\label{sec:corpus}

Each additional artifact in a family removes a different shortcut that the neural system might otherwise learn. Alternative Petri-net realizations discourage reliance on internal identifiers, serialization order, or one particular routing structure. Alternative event-log observations discourage reliance on accidental trace frequencies or trace presentation order. The designated process tree gives the decoder one consistent target even though several process models may be compatible with a finite observation.

Relation metadata controls which of these artifacts are treated as equivalent. For pairs certified under both recorded semantics, the alternative Petri-net realizations teach invariance to internal place names, transition identifiers, silent routing, and serialization. Ordinary, duplicate-prefix, and accepted M-pattern pairs may therefore act as strong positives when their visible-language and partial-order identifiers agree. The concurrency/interleaving families are a deliberate exception: their realizations share a complete visible trace language but have different recorded partial-order semantics, so they receive weaker relative-distance supervision rather than an unconditional positive label.

The generator performs six steps:
\begin{enumerate}
\item choose an ordinary random family or a controlled anchor motif;
\item construct the designated process-tree target;
\item construct two Petri-net realizations;
\item record visible-language evidence and partial-order information;
\item construct a trace pool and two finite log observations; and
\item relabel each observation consistently across modalities and expand the family into four rows.
\end{enumerate}
Figure~\ref{fig:corpus} groups these steps into four visual stages. Read it from left to right. The generator first selects an underlying tree or controlled motif. It then constructs alternative process-model realizations, records the relation between them, and samples two finite log observations. Only after these relationships have been established are observation-specific activity mappings applied and the family expanded into four stored rows. Family membership is fixed before the final Cartesian product; Appendix Fig.~\ref{fig:row-expansion} makes the observation-specific relabeling and row expansion explicit.

\input{figures/corpus}

All four rows from a family are assigned to the same split. Thus neither the two log observations nor the two Petri-net realizations of one generated family can cross a train--test boundary. The generator does not globally deduplicate designated trees or complete visible languages across independently sampled families, however. The experiment therefore measures generalization to unseen generated families, not strict behavior-disjoint or generator-shift generalization.

\subsection{Ordinary random families and controlled anchor families}

The corpus uses two complementary family types. Ordinary random families provide broad structural variation. Controlled anchor families isolate specific representation contrasts whose semantic relationship is known in advance.

Ordinary families are sampled topology first. The generator initially selects a root operator and recursively constructs an unlabeled tree topology. It rejects topologies that do not contain enough leaf positions to satisfy the required number of distinct activities.

Activities are assigned only after the topology has been accepted. The generator first assigns distinct labels until the activity floor is reached and permits label reuse only for subsequent leaves. This order prevents the activity requirement from changing the requested control-flow structure.

Before measuring or storing a target, the generator normalizes it with the same \texttt{pm4py-fold-v1} procedure used during evaluation. This PM4Py fold removes redundant silent leaves from sequence and parallel nodes, merges nested sequence, XOR, and parallel operators of the same type, and simplifies empty or unary internal constructs. XOR and parallel child order is canonicalized separately before folding. We call the normalized result the \emph{folded tree}; all size, depth, exact-match, and tree-edit measurements refer to this representation.

A candidate is retained only when its folded size, depth, and visible-activity count satisfy the ordinary profile. Otherwise, the generator restarts; it never inserts artificial sequential structure merely to reach the activity floor. After 4,000 unsuccessful attempts, generation fails explicitly instead of silently relaxing the profile. Appendix Fig.~\ref{fig:tree-sampler} visualizes this acceptance loop.

Controlled families place one of three small contrasts inside the same randomized context for both realizations. Their contexts remain between 4 and 12 nodes at every level and bypass the ordinary size, depth, and activity filters. Consequently, ``simple,'' ``medium,'' and ``complex'' refer to the corpus in which an anchor appears, not necessarily to the size of the anchor itself. This design keeps the diagnostic contrast stable while the surrounding ordinary families become larger and deeper.

The duplicate-prefix motif tests whether the representation ignores routing differences that leave both visible traces and the recorded partial order unchanged. The concurrency/interleaving motif tests whether it can recognize trace-language equality without erasing a partial-order difference. The M-pattern motif contrasts a block-structured target with non-free-choice routing while retaining the relation certified for the accepted context. Figure~\ref{fig:motifs} summarizes these structures.

\subsection{Relation records and event-log observations}\label{sec:relations}

For every pair of process-model realizations, the generator records three pieces of information separately. \emph{Evidence} states how the relationship was established, for example by exhaustive state-space exploration or construction isomorphism. \emph{Semantics} states whether the pair shares its complete visible trace language and whether it shares the recorded partial-order class. \emph{Training role} states whether the pair can be a strong positive, a weaker ordering example, or neither. Keeping these fields separate prevents a limited proof procedure from being mistaken for a behavioral semantics. Table~\ref{tab:relation-evidence} describes the evidence mechanisms.

When one net is created by a structure-preserving renaming of another, isomorphism certifies their equivalence without requiring trace enumeration. It is therefore an evidence mechanism for equality, not a separate or weaker behavioral relation.

Partial-order identity is stored independently from visible-language identity. A record may denote the same shared class, a concurrent realization, an explicitly interleaved realization, or unavailable information. A strong positive requires both the strong behavior identifier and the partial-order identifier to agree. A pair with the same exact visible-language identifier but different partial-order identifiers provides a weaker ranking constraint: it should be more similar than an unrelated pair, but not as similar as a pair that agrees under both recorded semantics. After the two Petri-net realizations have been constructed, the generator first builds a pool of visible traces. For a finite non-looping family, it explores both nets under the configured safeguards. If both explorations terminate and return the same complete trace set, the pair receives exact visible-language evidence. If either exploration reaches a safeguard, the collected traces may still agree, but complete-language equality is not claimed.

Ordinary looping trees may have an infinite visible language. For these families, equality between the two ordinary Petri-net realizations is certified by construction isomorphism rather than exhaustive enumeration. The generator then performs 512 seeded playouts, removes duplicate traces, and sorts the result to obtain a finite pool for log sampling. This pool is an observation source; it is not claimed to enumerate the infinite language.

The generator draws two 128-trace observations from the resulting pool. The \emph{cycled-coverage observation}, implemented as \texttt{uniform\_variants}, visits retained variants in round-robin order and then shuffles the selected traces. Its purpose is to reduce accidental frequency imbalance, not to estimate a real operational frequency distribution. When the pool contains more than 128 variants, this observation uses only the first 128 variants in deterministic sorted order; ``coverage'' therefore refers to the retained subset, not necessarily to the process model's full visible language.

The \emph{independently resampled observation} draws 128 traces with replacement. For example, from $\{ab,ac,ad\}$ a six-trace coverage observation contains two copies of each variant before shuffling, whereas a resample might be $ab,ab,ac,ab,ad,ac$. Its empirical frequencies may therefore differ substantially from those of the cycled-coverage observation even though both originate from the same trace pool. Presenting both observations teaches the neural system that finite-sample frequencies are properties of an observation, not necessarily properties of the underlying process. Persisted logs remain clean. Incompleteness and noise are introduced only as training-time augmentation so that quantitative evaluation is not confounded by unknown stored corruption.

Finally, each log observation independently induces a first-seen activity mapping. If one worked-example observation begins with \textsf{register}, \textsf{accept}, then \textsf{register} becomes $A_0$, \textsf{accept} becomes $A_1$, and \textsf{reject} becomes $A_2$. If the other begins with \textsf{register}, \textsf{reject}, the last two canonical names are reversed. Family labels absent from the finite observation are appended in stable tree/trace-pool order. The mapping is applied consistently to that observation, its target tree, and both corresponding Petri-net realizations. Because the observations may encounter activities in different orders, the same underlying activity can receive different canonical labels in the two stored observations. Positive relationships must therefore be determined from stored relation identifiers rather than surface labels.

\subsection{Generator implementation and relation checks}\label{sec:generation}

Reproducibility requires structural sampling, log sampling, and augmentation to remain independent. The global seed is therefore expanded with BLAKE2b into family-specific streams for the process structure, representation variant, playout, log observation, and augmentation.

Algorithm~\ref{alg:generation} condenses the preceding construction into implementation order. It shows where candidates are rejected and when relation metadata becomes available; the semantic meaning of each step is defined above.

\begin{algorithm*}[!t]
\centering
\caption{Behavior-family generation}
\label{alg:generation}
\begin{algorithmic}[1]
\Require complexity profile $c$, family target $n$, deterministic seed $s$
\State initialize split-local family list $\mathcal{F}\leftarrow\varnothing$
\State allocate controlled-motif and ordinary-root quotas
\While{$|\mathcal{F}|<n$}
  \State derive family-specific random streams from $s$
  \State sample an ordinary tree under $c$ or place a controlled motif in a shared context
  \State construct paired Petri-net realizations $N^{(1)},N^{(2)}$
  \State reject failed conversion, reachability, or dead-transition checks
  \If{$T$ is an ordinary looping tree}
    \State record construction isomorphism and simulate a seeded trace pool
  \Else
    \State enumerate each visible language under the configured safeguards
    \State reject empty or unequal collected languages
    \State record exact evidence if both searches finish; bounded evidence otherwise
  \EndIf
  \State construct cycled-coverage and independently resampled log observations
  \State apply each first-seen map and flatten two realization variants by two log observations
  \State store relation metadata, targets, seeds, and four rows
\EndWhile
\State verify coverage constraints and commit the split
\end{algorithmic}
\end{algorithm*}

For non-looping families, marking exploration stops after 5,000 visited states, 10,000 completed traces, visible length 32, or the silent-transition firing safeguard. During construction of the training split, a candidate whose certificate is neither exact nor isomorphic is rejected and replaced. Held-out splits may retain bounded-evidence families, but those families are not interpreted as exact visible-language positives. None occurs in the fixed evaluation subset: the simple subset contains 14 exact and two isomorphic families, while the medium and complex subsets each contain 12 exact and four isomorphic families.

The generator also rejects unreachable final markings and dead transitions. Its coverage check verifies the required motif quotas and confirms that every controlled motif appears in both Petri-net realization slots. The relation certificate is stored in every row rather than reconstructed later from surface similarity.

\subsection{Multimodal architecture}\label{sec:architecture}

The shared decoder predicts tree structure, operator arity, and visible activities. Its copy component can reuse activities represented in source memory. During generation, a small automaton tracks open child slots and masks illegal tokens. End-of-sequence is available only when every slot is filled; if the search budget is exhausted, deterministic completion closes the remaining slots.

The constrained procedure guarantees three structural properties: the prefix closes all required child slots, only permitted activity labels are emitted, and the resulting tree can be parsed and converted to a Petri net. The decoder must still learn every behaviorally important choice: which operator to select, where to place each activity, how large the tree should be, and whether the resulting process model reproduces the source behavior. Grammar validity therefore removes malformed outputs but does not solve process reconstruction. The evaluated synthetic policy restricts activities to the source alphabet and suppresses repeated visible labels. Because repeated labels can be legitimate, the external-log cases also evaluate the same source representation with that mask disabled.

\subsection{Training objectives}\label{sec:training}

The losses address three different failure modes. Reconstruction losses teach the decoder to produce the designated tree from each individual modality and from fused inputs. Alignment losses teach the semantic vectors which differences to ignore and which distinctions to retain. Regularization losses prevent the shared space from collapsing and stabilize structured generation. \subsection{Curriculum learning and checkpoint selection}\label{sec:curriculum}

Training begins with a bootstrapping problem. The neural system must learn cross-modal alignment, activity correspondence, and autoregressive tree grammar at the same time. Starting immediately with the largest trees couples these tasks strongly: an incorrect operator or arity changes the number of open child slots and can invalidate the interpretation of every subsequent token. The curriculum is therefore intended to establish closure, copying, and basic alignment on short trees before introducing deeper structures. Easier rehearsal batches remain active to limit forgetting, while controlled motifs provide stable representation anchors at every level. The study does not include a retrained no-curriculum ablation, so these are design motivations rather than causal findings.

Three terms describe the implementation. A \emph{complexity profile} specifies the ordinary-tree generator bounds. A \emph{complexity corpus}, or level, is one independently generated simple, medium, or complex dataset. A \emph{curriculum stage} specifies the mixture of those corpora currently used for training. Curriculum learning is the competence-gated transition between these stage mixtures.

Before each epoch, active levels with larger validation deficits receive more batch-selection weight. If $s_c$ is the balanced validation score for active level $c$ and $s_{\max}$ is the best active-level score, the implemented unnormalized weight is $w'_c=w_c[1+(s_{\max}-s_c)]$; the $w'_c$ values are then normalized. Advancement is considered only after at least five epochs in the current stage. Advancement from the medium stage has one additional retention condition: the simple-level validation score may not fall more than 0.02 below its previous best. At a transition, the active mixture changes and the learning-rate scheduler and early-stopping patience are reset. The loss jumps at epochs 6 and 11 coincide with these mixture changes; losses across stages describe different data mixtures and are not directly comparable.

\subsection{Fixed evaluation subset}

The full test split contains 512 families per level. Repeated beam decoding, behavioral simulation, and process-discovery evaluation over all three full splits would require a multi-hour exhaustive pass. The detailed evaluation therefore uses a deterministic family-complete subset of 16 families per level, chosen by interleaving motif and observation strata. This yields 48 families, 192 stored rows, and 768 decoding runs across the four source conditions. Results refer to this subset unless explicitly described as corpus statistics.

For decoded-process-model comparisons, tree-edit distance is normalized by the larger folded-tree size. We also require one common, computationally tractable distance for comparing generated families and decoded outputs. The experiment-specific behavior distance $d_B$ averages differences in three normalized distributions: complete trace variants available in the evaluation sample, boundary-aware directly-follows relations, and trace lengths:
\begin{equation}
d_B(f,g)=\frac{1}{3}\left(
 \lVert p_{\mathrm{var}}^f-p_{\mathrm{var}}^g\rVert_1+
 \lVert p_{\mathrm{df}}^f-p_{\mathrm{df}}^g\rVert_1+
 \lVert p_{\mathrm{len}}^f-p_{\mathrm{len}}^g\rVert_1
\right),
\label{eq:behavior-distance}
\end{equation}
Because each component is an $L_1$ distance between normalized distributions, $d_B=0$ means that all three summaries are identical and larger values indicate greater disagreement; its maximum is 2. This does not make $d_B$ a complete process-semantic distance. It may miss distinctions not reflected in these distributions, and related descriptors were used during training. Agreement with $d_B$ is therefore evidence about the experiment-specific ordering, not general behavioral equivalence.

Uncertainty is estimated by resampling complete families, never individual rows, with replacement \citep{Efron1994}. Percentile intervals summarize variation within the fixed subset; they do not include generator, training-seed, or checkpoint uncertainty.

For \RQthree, the row-level retrieval gallery retains the balanced expansion: the underlying tree contributes four instances, while each log observation and Petri-net realization contributes two. With 16 equally represented groups, random group-level Recall@1 is $1/16=0.0625$. Equal multiplicity leaves that prior unchanged, but multiple positive instances can make this protocol easier than a deduplicated gallery; the claim is therefore limited to the stated row-level setting. MRR can also depend on deterministic tie order and is treated as secondary. The discovery comparison evaluates log-decoded trees and Inductive Miner using footprint fitness and precision. Its coverage value is the fraction for which the footprint-conformance routine completes, whereas Table~\ref{tab:decode} reports completion of behavioral simulation; the two coverage rates are not interchangeable.

Its event-log, process-tree, and Petri-net files are encoded independently and translated back to a process tree to demonstrate file-level use.

\section{Reference implementation and interactive tool}\label{sec:reproduction}

\subsection{Implementation and access}

The open-source reference implementation is available in the public \href{https://github.com/fit-alessandro-berti/proc-rosetta}{ProcRosetta repository}, and a public, installation-free deployment of the interactive tool is available at \href{https://rosetta-pm.app}{rosetta-pm.app}. The Python implementation separates artifact I/O and preprocessing, modality-specific encoding, constrained decoding, behavioral evaluation, and presentation. Both the command-line utilities and the browser application call the same inference services and load the same serialized model format; the web application is therefore an inspection and execution layer over the evaluated implementation rather than a separate demonstration model.

The tool accepts XES event logs, PTML process trees, and PNML Petri nets. On import it parses and validates the source, records preprocessing warnings, constructs a first-seen canonical activity map, checks the checkpoint's vocabulary and size limits, and computes the modality-specific representation. The session workspace retains the source artifact, its canonical map, the checkpoint-specific embedding, and any subsequent decoding result. Content- and configuration-derived cache keys avoid recomputation while preventing embeddings or decodes produced under a different checkpoint or decoding policy from being silently reused.

For local deployment, the Streamlit front end can be started directly or through the supplied Docker Compose configuration. The container runs as an unprivileged user behind an NGINX reverse proxy. Checkpoints are selected only from a server-controlled directory because PyTorch checkpoint files must be treated as trusted executable content; the browser does not accept arbitrary checkpoint uploads. The evaluated checkpoint and the generated corpora are also provided as downloadable archives.\footnote{Evaluated checkpoint archive: \url{https://www.alessandroberti.it/checkpoint_rosetta_latest.tar.gz}}\footnote{Generated-data archive: \url{https://www.alessandroberti.it/data_rosetta_latest.tar.gz}}

\section{Discussion}\label{sec:discussion}

\subsection{\RQone: Why multimodal alignment succeeds}

The representation and generation results answer different questions. Alignment only requires related artifacts to occupy compatible neighborhoods. It does not require the semantic vector or source memory to preserve every decision needed to reconstruct one long discrete tree.

Behavior families expose nuisance variation directly. Finite sampling changes a log observation without changing its source process, and alternative Petri-net realizations change graph structure without necessarily changing recorded semantics. Relation-aware supervision therefore gives the encoders a reason to discard surface differences. The concurrency/interleaving contrast is particularly important because it prevents visible trace equality from being treated automatically as complete semantic identity. The result is a space that can support neighborhoods and retrieval even when the encoders share no input format.

The behavioral-ordering result is narrower. Its target is an experiment-specific descriptor related to training supervision, and deterministic features remain competitive. The contribution is therefore the availability of one learned interface from every modality, not the replacement of all modality-specific similarity measures.

\subsection{\RQtwo: Why semantic decoding remains difficult}

Some loss of exact match is unavoidable because a finite event log may be compatible with several process trees while training designates only one target. This ambiguity does not fully explain the results, however. Behavioral distance and footprint conformance also deteriorate, showing that many decoded outputs do not merely choose a different equivalent structure; they omit activities or place control-flow operators incorrectly.

Prefix decoding makes structural errors especially costly. Predicting the wrong operator or arity changes the number of child positions that remain open. Later tokens may therefore be locally valid under the altered prefix while being globally inconsistent with the intended process. The copy mechanism controls the activity vocabulary and the grammar controls well-formedness, but neither chooses the correct control-flow placement.

Three improvements follow directly from this diagnosis. First, decoding could generate several candidates and rerank them with conformance-aware scores. Second, training could include losses computed on complete decoded behavior rather than only token-level targets and latent descriptors. Third, the neural system could estimate confidence or abstain when the source log underdetermines a reliable process model. Translation from general Petri nets will additionally require an output language richer than block-structured process trees.

The duplicate-label comparison isolates one possible source of error. Disabling the mask does not change the top candidate for either real log, so their low conformance cannot be attributed to forced label uniqueness. In these cases the decoder instead omits activities and compresses control flow too aggressively.

\subsection{\RQthree: Appropriate and inappropriate uses}

The learned model is appropriate for encoding heterogeneous artifacts, retrieving related material, comparing neighborhoods, and proposing process-tree candidates for validation. A realistic use is a retrieve--propose--validate workflow. An incoming log or process model is first embedded to retrieve related known artifacts. The decoder may then propose one or more process-tree candidates. Established conformance routines and human inspection determine whether any candidate is behaviorally acceptable. This workflow uses the capability that currently performs well without treating syntactic validity as semantic evidence.

The learned model is not an unattended replacement for process discovery or conformance checking. Direct translation uses source memory, retrieval uses semantic vectors, and exploratory fusion combines semantic vectors before decoding. Simple mean fusion assumes that all modalities are equally reliable and that their semantic vectors are directly compositional. Its lack of reconstruction improvement suggests that future fusion should learn modality-specific confidence or attend jointly to source memories rather than averaging only their global summaries. Section~\ref{sec:reproduction} gives the operational commands used in the paper.

\FloatBarrier
\section{Limitations}\label{sec:threats}

\paragraph{Data and generalization.}
Quantitative training and evaluation use synthetic families generated by the same mechanism. The family-complete split prevents direct leakage of alternative rows from one family, but normalized trees and exact visible languages are not globally deduplicated across independently generated families. The synthetic artifacts also omit timestamps, resources, lifecycle attributes, drift, and meaningful activity labels. The two real logs provide only illustrative input-shift cases and do not have aligned reference trees and Petri nets. Finally, the decoder is restricted to block-structured process trees and therefore cannot reproduce every Petri-net behavior. The results consequently establish generalization to new families under the same generator, not industrial transfer, strict behavior-disjoint generalization, or unrestricted Petri-net translation. A stronger benchmark would combine real aligned artifacts, generator shift, global behavior deduplication, and explicit non-block-structured cases.

\paragraph{Evaluation and uncertainty.}
The detailed quantitative evaluation is based on a fixed subset of 48 families and one trained checkpoint from one random seed. Family-level bootstrap intervals describe variation among those selected families, but they do not include uncertainty from corpus generation, model initialization, optimization, or checkpoint selection. Some behavioral averages are additionally conditional on successful evaluator execution. Moreover, $d_B$ overlaps descriptors used during training, so its correlation with the learned space is not fully independent evidence. Larger family-complete evaluations, repeated training runs, independent behavioral measures, and unconditional failure reporting are needed before drawing stronger statistical conclusions.

\paragraph{Comparative evidence.}
The study compares \model with deterministic representation features and with Inductive Miner for log-to-tree discovery. It does not include every discovery method, a directly comparable learned multimodal system, or retrained ablations of the architecture, behavior-family design, curriculum, fusion method, and individual loss terms. The experiment therefore characterizes the complete implemented system but cannot identify which component is causally necessary for each result. Locked software environments, broader baselines, retrained ablations, and independent replication would strengthen that evidence.

\FloatBarrier
\section{Conclusion}\label{sec:conclusion}

\model demonstrates that heterogeneous process artifacts can currently be aligned more successfully than they can be translated. By training on relation-annotated behavior families, the neural system learns a common space in which event logs, process trees, and Petri nets from related families can be retrieved and compared. Grammar-constrained decoding solves a different problem: it ensures that every generated output is a well-formed process tree, but it does not ensure that the tree preserves the source behavior.

The synthetic experiments and two real-log illustrations show that direct event-log-to-tree generation remains below specialized process discovery and that syntactic constraints alone do not prevent activity omission or incorrect control-flow placement. The present value of \model is therefore as a shared representation and retrieval layer that can propose candidates for subsequent validation, not as an autonomous discovery system. The next step is to improve behavior-aware candidate generation and evaluate it on behavior-disjoint, real multi-artifact benchmarks, including structures outside the process-tree grammar.

SEQ(register request, LOOP(SEQ(AND(check ticket,

reinitiate request), XOR(reject request, pay compensation)).
\end{quote}

SEQ(register request, LOOP(AND(examine casually,
